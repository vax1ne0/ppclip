# Agents and sidebar

Attention statuses, pending confirmations, urgency ordering, and the Agents page extra columns and task hover card.

Open **Agents → an agent → Customization** to personalize its animated mascot. Pick any two body colors using color pickers or six-digit hex values, swap the gradient, or use the same color twice for a solid look. The 17 palettes remain available under **Preset starting points**, alongside **Surprise me** and nine expression previews. **Save appearance** persists the colors across the app; **Discard** restores the saved appearance. Invalid or incomplete hex values block saving. Expression previews do not change the agent’s runtime status. Unsaved changes use the agent page’s navigation guard, and failed saves preserve the draft for retry.

For an agent using an uploaded avatar, saving body colors switches it back to the animated mascot. The uploaded asset is retained. This tab uses Paperclip’s existing appearance JSON storage and company-scoped update endpoint. Optional `customColors: { a, b }` values override the fallback `paletteId`; both colors are validated and normalized to lowercase hex. Animated and static renderers share these values. Generated PNG URLs and cache keys include both colors, while muted avatars keep their muted presentation. Existing appearances remain compatible; no database migration is needed.

Body-color swatches open the same `react-colorful` saturation/hue picker used by team role groups. Changes update the active mascot player immediately without recreating it. Custom-color still portraits render locally as SVGs, including reduced-motion previews, so dragging never queues server PNG renders. A loading spinner covers missing portraits; the previous loaded image stays visible during replacement. Failed image loads retry twice before showing an unavailable icon, rather than agent initials.

**Gradient placement** offers separate center and rotation controls over a still preview, plus horizontal/vertical center and angle sliders. Placement is saved as optional `gradient: { x, y, angle }` (integer percentages 0–100, degrees −180–180). Reset restores the original centered 20° gradient. Changing colors preserves placement. Both GPU and SVG renderers honor it; PNG URLs and cache keys distinguish transforms. Muted portraits retain their original appearance.

**Adjust center of gradient** toggles a circular control filled with the renderer’s exact linear-light 50/50 blend color, plus a clipped midpoint line across the body. The target marks a point on that line, rather than a unique center of a linear gradient. Canvas definition changes run before paint so the target and color blend stay in the same frame; the mascot silhouette constrains the whole circle, including the rounded dome and lower corners. **Adjust gradient angle** toggles the rotation line separately, with a dashed orbit, larger invisible hit areas and a live coordinate/angle readout. Precision sliders remain available. The preview tracks the cursor across its entire box; the page-header mascot follows the cursor across the whole app viewport. The editor has a dedicated canvas so both stay interactive. While adjusting, the preview pauses its pose and cursor tracking but redraws each gradient change immediately, including with reduced motion enabled. Other placements retain the shared animation slot. The header and editor retain initialized contexts across scrolling, while the runtime suspends their offscreen frames and input. Pointer drags coalesce to one update per display frame and flush the last position on release. Appearance updates do not restart playback or redraw the unchanged pose. Live canvases use the device pixel ratio capped at 2, with face textures sized to the displayed mascot; exported SVG/PNG rendering is unchanged.

**Surprise me** generates two independent 24-bit hex colors, preserving gradient placement. A successful save publishes the confirmed appearance immediately to the agent-list, detail and identity caches before refreshing them. Generated thumbnails up to 64px render locally instead of waiting for a cold server PNG worker. A bounded 128-entry cache shares in-flight and completed renders across matching avatars. Uploaded images and Storybook asset URLs retain their original paths. Custom portraits use the same size-specific geometry, face, shading and framing as original palette portraits, and load eagerly so sidebar thumbnails reflect the saved design. Shared tooltip hooks use the existing gray popover surface, foreground and border tokens.

Agent edit forms use the layout’s action dock outside the scrolling content. Customization, instructions and configuration share this dock so page padding cannot leave visible content below the save bar.

**Harness / Runtime → Agent identity → Role** edits the organizational role used by Team role groups. Title remains a separate display label. Existing legacy roles stay selectable until replaced.

Configuration saves publish the server-confirmed agent to matching company list and detail caches immediately, including the destination cache for a renamed agent. The saving/navigation lock ends with the update request; revision and roster refreshes run in the background. The form clears only submitted fields, preserving edits made during a pending save and keeping failed drafts available for retry. Unrelated lifecycle refreshes do not discard drafts.

Agent chat sidebar rows also show the configured model with a provider mark. An unset model is labeled “Model not set”; the full model and harness are available on hover. This follows the Agents page extras switch. Agent model pickers require an explicit choice and do not offer a default-model option.

Chat tabs use the conversation owner's last sent prompt for ordering. Opening a tab, agent replies, and runtime/attention changes do not move it. Unused agents follow alphabetically; this order is separate from the main sidebar's Urgent agents first switch.

New-agent setup shows the same model picker on both **Connect** and **Configure**, preserving the selection between steps. Choose the model before testing a saved subscription, API key or new sign-in. If model discovery fails, an explicit model ID can be entered manually.
